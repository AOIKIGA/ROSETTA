## 1. 要做什么

构建一个个人在本机使用的编码 Agent：在指定工作区内理解问题、读取项目、提出修改、经过权限判断执行工具，并保存可继续的会话。首先支持 CLI；macOS 为本机验证平台，Linux 为第二目标平台。

暂定项目名 ROSETTA。当前按单用户、一个默认 Agent 设计。多个 session 是这个 Agent 的不同会话，不是不同进程。未来确实需要独立配置与权限时，再增加命名 Agent，每个 Agent 可有独立 state 目录和 daemon。

完整的 v0.1 目标是“可持久化对话 + 一个真实 Provider + 工具循环 + 受控读写和命令执行”。本次完成的是 M1 通信骨架；以下明确区分已实现与规划。

## 2. 为什么这样选

| 领域 | 决策 | 理由与代价 | 阶段 |
|---|---|---|---|
| 语言 | Go，项目固定 1.27.2 | 并发、HTTP、进程和文件操作可以从标准库起步；取消和资源清理仍需显式设计 | M1 |
| 组织方式 | 一个 Go module、一个二进制、内部包分层 | 便于一个人构建、调试和发布；包边界承担模块化职责 | M1 |
| Agent 执行 | 自己写小型运行时 | 可理解每一步状态变化；需要自己负责工具协议、错误和预算 | M1–M4 |
| CLI | 标准库 `flag` | 当前只有少量命令；需要复杂交互时再评估 TUI 或命令框架 | M1 |
| 本地通信 | HTTP over Unix Socket，响应为 NDJSON | 使用标准 HTTP 路由、状态码和请求取消；本地连接不占 TCP 端口 | M1 |
| 日志 | `log/slog`，先写 stderr | 结构化字段便于定位 run；第一版不保存 prompt、密钥和完整工具输出到日志 | M1 |
| 持久化 | SQLite，`database/sql` + `modernc.org/sqlite` | 本地事务和查询方便，无额外数据库服务；写事务要短，驱动依赖会增加构建体积 | M2，版本届时锁定 |
| 配置 | JSON 配置 + 明确的默认值；密钥由环境变量读取 | 配置格式接近已有学习材料，减少引入依赖；未知字段报错，避免拼错后静默无效 | M2–M3 |
| 模型接入 | 首个真实适配器选 OpenAI Responses + 官方 Go SDK | 官方推荐新项目使用 Responses；把供应商类型封装在适配器内 | M3，待接入可用凭证 |
| 模型选择 | 模型 ID 显式配置 | 不把价格或可用性可能变化的模型名硬编码为架构前提；接入时按账号权限和预算验证 | M3 |
| 工具 | 内置 Go 工具，先读后写，再命令执行 | 每增加一种副作用，都同步增加约束与失败处理 | M3–M4 |
| 测试 | 标准 `testing`、`httptest`、竞争检测、离线 Provider | 关键边界可自动复现，不依赖模型随机输出和费用 | M1 起 |

暂不引入 Redis、消息队列、微服务、向量数据库、通用依赖注入框架或完整 Agent 框架。当前需求可以由一个进程和一个本地数据库完成；加入这些系统会增加故障点和学习量。

官方依据：

- [Go 发布与支持策略](https://go.dev/doc/devel/release)：本次核对的稳定版本为 1.27.2。本机原全局版本为 1.25.4，已下载项目所需工具链，未替换全局安装。
- [Go HTTP 标准库](https://pkg.go.dev/net/http)：用标准服务器、客户端和请求上下文组织通信。
- [Go context](https://pkg.go.dev/context)：传播取消和期限。
- [SQLite 的适用场景](https://www.sqlite.org/whentouse.html)：面向设备本地存储，适合低写入并发的单机应用。
- [modernc.org/sqlite](https://pkg.go.dev/modernc.org/sqlite)：提供不依赖 CGo 的 SQLite 驱动。M2 再固定版本并运行事务测试。
- [OpenAI Responses 指南](https://developers.openai.com/api/docs/guides/migrate-to-responses)：新项目推荐 Responses；这不代表其他供应商兼容其全部协议。

## 3. 分层和一次请求

```mermaid
flowchart LR
    U[用户] --> CLI[CLI]
    CLI --> C[本地客户端]
    C -->|HTTP / Unix Socket| D[Daemon：校验与准入]
    D --> R[Runtime：执行 turn]
    R --> P[Provider：模型适配]
    P -->|文本或工具请求| R
    R -->|事件| D
    D -->|NDJSON 流| C
    C --> CLI
```

代码依赖原则：协议类型不依赖 HTTP；Runtime 不依赖 CLI、socket 或具体 SDK；Provider 实现 Runtime 所需接口；入口负责把具体组件组装起来。CLI 客户端不导入 daemon 实现。

M1 的 Runtime 只接收一条文本并产生文本事件。接入模型和工具时，接口会演进为结构化消息及模型事件。当前不预建几十个无实现的接口。

未来 Runtime 调工具、读存储，也不应负责监听端口或处理 CLI 参数。Daemon 决定“是否允许这次执行”，Runtime 决定“这次执行如何推进”。

## 4. 与参考项目的关系

| 保留 | 调整或后置 |
|---|---|
| CLI 与服务共用二进制 | 先以前台 `serve` 运行；后台 start/stop 后置 |
| Runtime 与 Daemon 分工 | 不复刻 Rust 的每一层转发函数 |
| 流式事件、session 单写 | HTTP + NDJSON 替代自定义 JSON-RPC 帧 |
| Provider 适配层 | 从一个真实适配器开始，后续按实际需求扩展 |
| 取消、超时和生命周期边界 | 用 context、显式 Close/defer 和任务退出等待落实 |
| 独立 state 与 workspace | M1 只有 state；M2 引入 session 的工作区快照 |
| 恢复与审计意识 | 先写清工具副作用记录，再扩展 goal 自动续跑 |
| 多入口的可扩展性 | ACP、Gateway、IM 在核心稳定后做协议适配 |

本地 HTTP 是我们自己的协议，不等于对外 Gateway。以后开放远程入口需要单独设计认证、授权和连接策略。ACP 也需要专门适配，不是当前接口自动兼容。

## 5. 先把容易含糊的规则写清楚

### Session、Turn、Round

- Session：一段可持续的对话，未来持有消息历史、模型和工作区配置。
- Turn：一次用户输入到本次执行终止。
- Round：一个 turn 中的一次模型调用。模型请求工具后，执行工具再调用模型，就进入下一 round。
- Goal：跨多个 turn 的长期目标，第一版不做自动续跑。

M1 的 `session_id` 只是并发隔离键，没有历史存储。M2 会把它变成真实持久化实体。

### 并发和退出（M1 已实现）

1. 同一 session 同时只运行一个 turn；冲突立即返回 409，暂不排队。
2. 同一 daemon 最多四个 turn；超额返回 429。
3. 单 turn 最多两分钟。客户端关闭连接或按 Ctrl+C 时，通过请求 context 取消执行。
4. 慢客户端每次写事件最多等待五秒。当前同步传递事件，不维护无界缓存。
5. daemon 退出先取消请求，再等待服务关闭；超时强制关闭连接。
6. 同一 state 目录只允许一个 daemon，使用进程存活期间持有的文件锁；锁文件保留，socket 随关闭清理。

### 持久化与恢复（M2/M4 规划）

SQLite 是消息、turn 和工具执行记录的事实来源；流式文字是显示过程，不等于已经提交的消息。模型调用期间不持有数据库写事务。

基本实体是 `sessions`、`turns`、`messages` 和后续的 `tool_runs`。先使用自增消息序号与唯一约束，完整 schema 在 M2 落地。turn 状态先采用 `running / completed / failed / canceled / interrupted`。

接收输入时短事务写入用户消息与 running turn；成功时短事务保存最终消息并标记 completed；失败也记录原因，不假装用户没有发过消息。进程重启后将残留 running 标记 interrupted，先要求新请求继续，不自动重放工具。

例如“文件已经写入，但结果还没存入数据库就崩溃”：重启后不能因为缺少成功记录就再次执行任意命令。需要记录执行意图、结果和不确定状态。外部副作用与本地事务通常无法一起提交，因此第一版不承诺所有工具都恰好执行一次。

### 工作区与权限（M3/M4 规划）

工作区来自 session 快照，不使用进程全局 chdir 来切换不同会话。工具拿到显式的 workspace；命令用自己的工作目录参数。

读取工具限制路径和输出大小。写入工具展示精确变更、申请审批并检测文件是否已被其他人修改。命令工具增加时间、输出和进程组清理规则；同一工作区的修改需要协调，session 单写并不能防止两个 session 同改一个文件。

路径规则、审批和命令限制各有作用，但不是完整 OS 沙箱。第一版先在用户控制的本地项目使用；执行不可信项目或开放远程入口前，再引入隔离后端并验证逃逸边界。

### 失败与重试（M3/M4 规划）

第一次先实现清楚的失败状态，再加入有限重试。遇到部分文本输出、工具已开始执行或供应商状态不确定时，不整轮透明重放。对可重试请求，设置总期限和次数；模型重试不能绕开工具副作用记录。

### 上下文（M3/M5 规划）

M3 保存历史并设置输入预算及输出预留；超预算先明确报错，不能无限发送。M5 再做摘要压缩，保留近期消息、必要的工具调用/结果配对和用户约束。阈值依模型能力配置，不把参考文档中的 80% 当成所有模型的通用保证。

## 6. 后续再做的功能

子 Agent、MCP、Skills、长期记忆、自动目标续跑、Cron、热重载、插件、Checkpoint/Rewind、ACP 和 Web 界面都有明确的扩展空间，但不同时开工。先通过 M1–M4 的验收，再选择确有使用场景的一项。

下一项确定为 M2：持久化会话与配置。这样在接真实模型前，就能解释“发过的消息存在哪里、重启后发生什么”。
