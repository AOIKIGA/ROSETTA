## 从学习记录到实现规格仍需补齐的内容

| 领域 | 当前材料已有 | Go 设计中需要明确 |
|---|---|---|
| RPC 与事件流 | 方法路由和事件示例 | 帧结构、请求/运行/事件 ID、终态、错误码、慢消费者、断连及重连策略 |
| 会话存储 | SessionEntry、预提交、最终提交 | 完整 schema、事务边界、迁移、部分成功和崩溃恢复 |
| 工具执行 | 调用与结果循环、审批、取消 | 工具参数校验、输出上限、超时、失败结果、重复执行与已发生副作用的记录 |
| 并发与调度 | session 单写、准入、子任务额度 | 队列上限、公平性、跨 session 文件冲突、父子取消、退出等待 |
| Provider | 统一接口、流事件、fallback | 能力声明、工具参数分片组装、部分流失败、重试边界与用量统计 |
| 上下文压缩 | 80% 阈值、摘要替换、冷却 | 输入输出预算、保留消息、工具调用与结果配对、失败时行为 |
| 审批与权限 | 三类交互门控、审批记忆 | 请求归属、超时、断连、过期答复、授权范围和撤销 |
| Goal 与恢复 | Active 对账和不同恢复动作 | 完整状态机、续跑条件、预算耗尽、停止和终止原因 |
| Checkpoint | 回退消息和文件概述 | 文件变更捕获时机、外部修改冲突、命令修改文件的覆盖范围及回退失败 |
| 扩展机制 | MCP、插件、Skills、Hooks 等入口 | 接口与生命周期、权限继承、版本兼容；按开发阶段补充 |
| 验收 | 主链路说明 | 正常流程、取消、审批拒绝、模型故障和重启恢复的验收场景 |

以上缺项可以由新项目作出明确决策，不要求继续还原原项目的全部细节，也不要求全部纳入第一版。
